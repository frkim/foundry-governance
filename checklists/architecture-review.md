Check the box when the review action is performed, **not** as a substitute for its result. For every item record `pass`, `fail`, `hold` or `n/a`; `n/a` requires written scope rationale and independent reviewer approval. Missing/uncertain evidence or approvals create a **hold**; failed required controls create a **block**. Both prevent release. An eligible, independently approved, unexpired exception must be explicitly recorded; it does not turn failed evidence into a pass.

- [ ] **ARC-01 — Confirm purpose, ownership, inventory and risk profile.** Business Owner identifies allowed tasks/users, prohibited use, named technical/operations owners and risk/baseline selection. **Block:** unowned operation or unapproved high-risk scope. [GOV-01](../governance/controls/README.md#gov-01), [GOV-12](../governance/controls/README.md#gov-12); [governance model](../docs/01-governance-model/README.md).
    - Evidence: `<approved registration and impact assessment URI>`; reviewer/date: `<...>`; status: `<...>`; N/A rationale / finding / exception: `<...>`.
- [ ] **ARC-02 — Approve topology and isolation.** Platform Owner shows tenant/subscription/resource/project and external-hosting boundaries, production separation, trust zones, ingress/egress and supported network controls. Test cross-boundary access; do not treat project membership as sufficient isolation. **Block:** unauthorized boundary crossing. [GOV-02](../governance/controls/README.md#gov-02); [resource topology](../docs/02-resource-topology/README.md), [network security](../docs/04-network-security/README.md).
    - Evidence: `<diagram, configuration, negative access tests and capability verification URI>`; reviewer/date: `<...>`; status: `<...>`; N/A rationale / finding / exception: `<...>`.
- [ ] **ARC-03 — Validate every geographic route.** Data/Model Owners distinguish hosting, model processing, data/log storage, global/data-zone/regional deployment types and all fallbacks. Approve provider and residency implications explicitly. **Block:** a route violates mandatory residency or activates an unapproved fallback. [GOV-02](../governance/controls/README.md#gov-02), [GOV-05](../governance/controls/README.md#gov-05); [model governance](../docs/11-model-governance/README.md), [data governance](../docs/05-data-governance/README.md).
    - Evidence: `<flow map, exact deployment-type export, provider sources and Data Owner decision>`; reviewer/date: `<...>`; status: `<...>`; N/A rationale / finding / exception: `<...>`.
- [ ] **ARC-04 — Trace identities and authorization end to end.** IAM/Application Owners separate caller, runtime, pipeline, gateway and tool/MCP principals; document grants, token audiences and per-operation server-side authorization, including delegation. **Block:** prompts, mutable headers or authentication alone confer backend authority. [GOV-03](../governance/controls/README.md#gov-03); [identity and access](../docs/03-identity-access/README.md).
    - Evidence: `<identity/scope matrix, credential lifecycle and denied-operation tests>`; reviewer/date: `<...>`; status: `<...>`; N/A rationale / finding / exception: `<...>`.
- [ ] **ARC-05 — Approve data, retrieval and memory handling.** Data Owner documents permitted classes/purposes, retrieval ACLs, per-user/tenant memory boundaries, provider use, redaction and numeric retention/deletion/hold rules across dependencies and telemetry. **Block:** disallowed disclosure or cross-user memory access. [GOV-04](../governance/controls/README.md#gov-04); [data governance](../docs/05-data-governance/README.md).
    - Evidence: `<data-flow schedule, privacy decision, redaction/deletion and retrieval isolation tests>`; reviewer/date: `<...>`; status: `<...>`; N/A rationale / finding / exception: `<...>`.
