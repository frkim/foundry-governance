A checked box means the action was reviewed; record the actual result separately. Every item needs evidence, reviewer/date and `pass`, `fail`, `hold` or `n/a`. `n/a` requires a written scope reason and independent approval. Missing or uncertain evidence/approvals are a **hold**; demonstrated failure of a required control is a **block**. Both stop release. Only an eligible, independently approved, unexpired, scope-matched exception can permit the corresponding deviation; non-waivable obligations cannot be excepted.

## Dependency and execution safety

- [ ] **SEC-05 — Verify model/tool/skill supply-chain approval.** Component Owners prove trusted provenance, exact reviewed versions/schemas/digests, supplier terms, least capability and drift response, including fallbacks. **Block:** unapproved component or capability widening. [GOV-05](../governance/controls/README.md#gov-05); [tools](../docs/08-tools/README.md), [model governance](../docs/11-model-governance/README.md), [skills](../docs/16-skills/README.md).
    - Evidence: `<registrations, dependency manifest, specific immutable skill versions, source/digest evidence, drift-test outcome and shared-default affected-consumer regressions/approvals>`; reviewer/date: `<...>`; status: `<...>`; N/A rationale / finding / exception: `<...>`.
- [ ] **SEC-06 — Review MCP server trust and each tool independently.** MCP/IAM Owners verify discovery source/schema hash, server authentication, expected OAuth resource/audience where used, no passthrough of inbound client access tokens to downstream services, and per-tool server-side authorization. Treat descriptions, inputs and outputs as untrusted. **Block:** wrong-audience tokens, unknown tools or unauthorized direct calls succeed. [GOV-03](../governance/controls/README.md#gov-03), [GOV-05](../governance/controls/README.md#gov-05), [GOV-06](../governance/controls/README.md#gov-06); [MCP](../docs/09-mcp/README.md).
    - Evidence: `<MCP registration, discovery snapshot/hash, token/authorization/drift/malicious-output tests>`; reviewer/date: `<...>`; status: `<...>`; N/A rationale / finding / exception: `<...>`.
- [ ] **SEC-07 — Execute adversarial guardrail tests.** Security/Evaluation Owners test direct and indirect injection, malicious retrieval/tool responses, exfiltration, output handling, multi-agent escalation and guardrail failure paths. **Block:** approved release thresholds fail without an eligible approved risk decision. Model filters/prompts alone are not sufficient. [GOV-06](../governance/controls/README.md#gov-06), [GOV-07](../governance/controls/README.md#gov-07); [agent security](../docs/07-agent-security/README.md), [quality/evaluation](../docs/12-quality-evaluation/README.md).
    - Evidence: `<versioned dataset, per-case outcomes, baseline comparison and independent gate decision>`; reviewer/date: `<...>`; status: `<...>`; N/A rationale / finding / exception: `<...>`.
- [ ] **SEC-08 — Prove consequential-action approval cannot be bypassed.** Business Process/Tool Owners bind independent approval to actor, transaction, target, action/arguments and expiry; recheck server permissions at execution. **Block:** self-approval contrary to segregation rules, modified/expired/replayed approvals, or execution when required authorization/approval is unavailable. [GOV-06](../governance/controls/README.md#gov-06); [human-in-the-loop](../docs/23-human-in-the-loop/README.md).
    - Evidence: `<approval matrix, binding and denial/replay/outage tests, authorized approver identity>`; reviewer/date: `<...>`; status: `<...>`; N/A rationale / finding / exception: `<...>`.
